# Task 1.8.1.1.1: Implement Release Creation Workflow

## Scenario

Given a HACS integration repository
When I create a new release
Then the release tag should match the manifest.json version
And release notes should document changes and fixes
And release should be properly tagged in Git
And HACS should detect the new version within 24 hours

## Instructions for Coding LLM

Implement a release creation workflow:

1. Develop a script to automate the release process
2. Ensure the script updates the version in manifest.json
3. Implement release notes generation:
   - Fetch all commits since the last release
   - Categorize commits (e.g., features, bug fixes, documentation updates)
   - Format the categorized commits into a readable release notes structure
   - Include any breaking changes or important notices
   - Allow for manual editing or addition of information
   - Implement error handling for Git operations and data processing
   - Ensure the generated notes follow a consistent format across releases
4. Create a Git tag matching the new version
5. Generate a GitHub release with the same version number, including the generated release notes
6. Implement error handling and logging throughout the workflow
7. Ensure HACS version detection:
   - Verify that the release is properly formatted for HACS detection
   - Implement a check to confirm that the release is visible on the GitHub API
   - Create a test that simulates the HACS version detection process
   - Implement a waiting mechanism that checks for HACS detection at regular intervals
   - Set up alerts if HACS hasn't detected the new version within 24 hours
   - Document the steps for manual intervention if automatic detection fails
   - Implement logging for the detection process for troubleshooting

Please implement the release creation workflow based on the above instructions. Ensure that the implementation includes a script that automates the entire release process, updates the version in manifest.json, generates comprehensive release notes, creates a Git tag, generates a GitHub release, and verifies HACS detection. This workflow should streamline the release process, maintain consistency across all aspects of the release, provide users with clear, well-structured information about each new version, and ensure that new releases are promptly detected by HACS for timely updates.
