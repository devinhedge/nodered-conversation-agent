# Task 1.2.1.2: Create Unit Tests for Integration Directory Structure Validation

## Scenario

Given a custom component repository
When I validate the directory structure
Then all integration files should exist under `/custom_components/{domain}/`
And the domain should be consistent across all configuration files
And required files (__init__.py, manifest.json) should be present

## Instructions for Coding LLM

1. Create unit tests to cover all aspects of the acceptance criteria:
   - Test with valid directory structures
   - Test with invalid structures (missing files, inconsistent domain names, etc.)
   - Test edge cases (empty directories, extra files, etc.)

2. Implement tests for error handling and logging:
   - Verify that appropriate error messages are generated for different failure scenarios
   - Check that detailed information is logged during the validation process

3. Create tests for different integration types and structures:
   - Test with various HACS integration types
   - Verify that the validation function is flexible enough to handle different structures

4. Implement performance tests:
   - Create tests with large integrations containing many files
   - Measure and assert on the execution time of the validation function

5. Test integration with pre-commit hooks or CI/CD pipelines:
   - Mock the environment of a pre-commit hook or CI/CD pipeline
   - Verify that the validation function can be called and returns results as expected in these contexts

6. Implement tests for consistency checks:
   - Verify that the domain name is correctly checked across all configuration files
   - Test scenarios with inconsistent domain names in different files

Please implement comprehensive unit tests for the integration directory structure validation function based on the above instructions. Ensure that all possible scenarios are covered and that the tests are easily maintainable.
